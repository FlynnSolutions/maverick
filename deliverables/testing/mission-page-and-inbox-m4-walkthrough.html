Mission page and inbox · milestone 4

The question reaches you, and the page is where you start

The app polls every project's workspace every 15 s and shows a macOS notification once for each question that is new since the last poll; a click brings the window up on that mission's Progress. The app reopens on the workspace of the project you last had open, with a "change project" button for the picker. The docs name the four anchors, the inbox and the status words.

Before you start: run the app from this branch on 8767

Most of this milestone lives in the Electron app (app/main.mjs), so this walk is in the app, not a browser tab. A browser tab gets no notification.

  1. Stop the server on 8767. When this was written it was a node started from the main checkout (/Users/coryflynn/Projects/maverick, on main), which has none of this milestone. lsof -nP -iTCP:8767 -sTCP:LISTEN names it.
  2. Once: cd /Users/coryflynn/Projects/maverick/.claude/worktrees/mission-page-and-inbox-integration-root/app && npm install. That puts Electron 44.7.0 from the lockfile into app/node_modules (ignored by git). It is the app's declared dependency, not a new one; it was simply never installed here.
  3. In the same folder: SESSION_CONSOLE_PORT=8767 npm start. Nothing answers on 8767, so the app starts this branch's server inside itself, on your real home. Keep that terminal in view: the poll's errors print there.

If the window never opens or the terminal shows an error importing a .ts file, mark n1 to n3 and w1 to w3 blocked (⛔) with the error as the note; nobody has run this Electron build with src/notify.ts yet. If notifications never show, look at System Settings, Notifications, Electron (and Focus) before failing a case.

A new question reaches you

howThe live mission is at review and asks nothing, and only a flying mission can be paused, so these cases make a question by hand: a planned mission record, which the workspace reads as one question, "the plan is waiting for approval". The sweep leaves planned missions alone. Never press approve on it; delete the file when done (n3 does).

Opening the app announces nothing that was already waiting
Steps
  1. Quit the app. Write the question while it is closed: 
    cat > ~/.claude/console-sessions/missions/maverick/walkthrough-m4-ping.json <<'EOF'
{"id":"walkthrough-m4-ping","project":"maverick","name":"walkthrough m4 ping","brief":"A mission written by hand so the app has a question to announce. Delete the file when done.","status":"planned","created":"2026-10-14T12:00:00.000Z","plan":"","repos":[],"land":"pr","trackerIndex":0,"milestones":[]}
EOF
  2. Launch the app and watch for 40 s (two polls past the first).
Expected
  • Needs you on Maverick's workspace has a row the plan is waiting for approval for walkthrough m4 ping, with an approve button (do not press it).
  • No notification at all: not for this question, not for any other project's open questions. The first poll only remembers.
A question that appears is announced once
Steps
  1. With the app running: mv ~/.claude/console-sessions/missions/maverick/walkthrough-m4-ping.json ~/Desktop/. Wait 20 s.
  2. mv ~/Desktop/walkthrough-m4-ping.json ~/.claude/console-sessions/missions/maverick/. Note the time, then watch for 45 s more.
Expected
  • Moving it out: no notification (a question going away says nothing).
  • Moving it back: within 15 s, exactly one macOS notification, title walkthrough m4 ping, body the plan is waiting for approval. A question that went and came back counts as new; that is by design.
  • No second notification for it in the 45 s after, while it stays open.
Clicking it brings the window up on that mission
Steps
  1. Minimize the app window (Cmd+M). Repeat n2's two moves to get a fresh notification.
  2. Click the notification (from Notification Center if the banner has gone).
  3. Clean up: rm ~/.claude/console-sessions/missions/maverick/walkthrough-m4-ping.json, then go back to the workspace.
Expected
  • The window comes back from the Dock and to the front, on the mission page for walkthrough m4 ping, scrolled to Progress. Before approval Progress reads Nothing has flown yet...; the approve control is under Plan just above. The rail's word is waiting for you.
  • After the rm, the workspace's Needs you row for it is gone within a few seconds and no notification fires.
