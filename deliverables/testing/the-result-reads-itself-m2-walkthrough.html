Before you start: a scratch server on 18768

The server on 8767 runs main, which does not have this milestone, so it cannot show it. Leave it alone. Every case uses a scratch server on 18768, run from the integration worktree. It serves a copy of the mission-page-and-inbox record, set to review so no sweep touches it.

Marking a finding later commits to the project's checklist and to the mission ledger. In the copy, both point at a throwaway git repo in /tmp/rri-m2. The diffs are still read from the real branches, so the merged-file rows are real, but nothing is written to them.

Known going in

The RIO passed both tasks and left these open. They are not cases, except where one asks for your call. Note any you hit and think should be fixed.

count vs badge
A bucket's count includes findings you have already marked, but the rail counts only unread ones. Case m1 asks for your call on this.
keyboard focus
Every view the stream sends puts the later buttons back in place, and marking a finding disables its controls. Either way, keyboard focus drops to the page. Case m3 asks for your call on this.
flicker
For a few milliseconds between your click and the next view, a ticked box can show unticked again. A second click does no harm.
nothing to fix
Only "Fix before merge" opens on load. If it is empty, every bucket is closed and the findings are hidden. The RIO suggests opening the first bucket that has findings in it, which is a one-line change.
directory areas
A finding whose area is a directory, such as web/mission, puts its chip on every merged row under it, including rows from other tasks. None of the seeds does this.
screen readers
Each why button reads only as "why". The kind (BLOCKER, NOTE, UNVERIFIED) is given only in the chip's tooltip.
old lines
These findings were written before the new format, and milestone 1's parser reads some of them oddly. You will see headlines like types., and areas like verified, agrees with 55126ca and scope. That is the parser, not this milestone, but this page is where it shows.
