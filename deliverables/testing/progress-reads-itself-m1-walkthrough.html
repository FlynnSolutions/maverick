The ledger says how many

A pass with notes writes a count, not the notes

This drives the real transitions(), the function the sweep writes ledger lines with, over three tasks moving to passed: one with 10 notes and 1 unverified claim (the done-when's own numbers), one plain pass, and one the merge-with-notes rule settled after its last attempt.

Steps
  1. node --input-type=module -e '
import { transitions } from "./src/missions.ts";
const carried = [...Array.from({ length: 10 }, (_, i) => `NOTE(area${i}, ship): note ${i + 1}.`), "UNVERIFIED(web, check): The page was not loaded."];
const t = (id, title) => ({ id, title, status: "reviewing" });
const before = { milestones: [{ n: 1, tasks: [t("m1-t1", "Walk"), t("m1-t2", "Plain"), t("m1-t3", "Long")] }], log: [] };
const mission = { milestones: [{ n: 1, tasks: [
  { id: "m1-t1", title: "Walk", status: "passed", verdict: "pass with notes", carried },
  { id: "m1-t2", title: "Plain", status: "passed", verdict: "pass" },
  { id: "m1-t3", title: "Long", status: "passed", verdict: "mixed", note: "the RIO said mixed after 3 attempts with no blocker open", carried: carried.slice(0, 2) },
] }] };
for (const line of transitions(before, mission, "2026-10-14 12:00")) console.log(line);'

  • 2026-10-14 12:00 m1-t2 Plain: reviewing to passed (RIO: pass), with no count at all.
  • 2026-10-14 12:00 auto: m1-t3 Long: reviewing to passed (RIO: mixed) with 2 notes carried: the RIO said mixed after 3 attempts with no blocker open. The count sits right after the verdict, no , 0 unverified, and the note no longer repeats the count (it used to end merged with 2 note(s) carried).
  • No [carried: in any of the three lines.
