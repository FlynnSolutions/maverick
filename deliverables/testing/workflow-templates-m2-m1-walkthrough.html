Pick a template, fly Light, and keep unverified work on its branch

Maverick · workflow templates m2 · milestone 1 of 1 · built on mission/workflow-templates-m2

A new mission now starts from a template card: Mission (the full flight, preselected), Light (build and merge with no review, proof or walk), or a project's own file. A Light mission flies with Wingmen only, its page says which template it runs and where it is in it, and because nothing verified its work it stays on its mission branch: a project set to land by pull request or push is refused at the gate and again at landing.

Get it running

In the mission branch's own checkout, seed the invented project Saltmarsh (one project template, survey, one broken one, quick, land by merge) and start that checkout's server on its own registry, port 8797. The seed never touches ~/.claude/session-console, so your everyday Maverick on 8766 neither sees nor sweeps it.

cd ~/Projects/maverick/.claude/worktrees/workflow-templates-m2-integration-root && node tools/seed-templates.mjs --dir /tmp/mv-walk
SESSION_CONSOLE_HOME=/private/tmp/mv-walk/console SESSION_CONSOLE_SESSIONS=/private/tmp/mv-walk/sessions SESSION_CONSOLE_PORT=8797 MAVERICK_SERVER_LOG=/private/tmp/mv-walk/server.log node server.ts

Once, before the first flight, let Claude Code trust the invented repo (preflight refuses an untrusted folder): run this, accept the prompt, then /exit. The journeys run real Claude sessions on your login against this invented project only.

cd /private/tmp/mv-walk/saltmarsh && claude

Then open 127.0.0.1:8797/?project=saltmarsh&view=workspace. Walk the journeys in order: j2 names the Light mission that j3, j4 and the look cases reuse. When you are done, stop the server and run node tools/seed-templates.mjs --clear --dir /tmp/mv-walk.
