The result reads itself · milestone 3

Ask the record

Result on the mission page now opens with "What I must read". Its summarize button posts to /api/missions/<id>/summarize, which spawns one read-only session (the rio agent, with no Edit or Write). That session reads the mission's report and every carried finding and writes three bullets to <record dir>/<id>-summary.md. When the session finishes, the sweep reads the file into the record as summary: { at, text } and the page shows the bullets. While it runs, the button reads summarizing... and is disabled. You walk it in the browser against a scratch copy of the finished mission-page-and-inbox mission. Two cases spawn a real Claude session each.

Before you start: a scratch server on 18769

The server on 8767 runs main, which does not have this milestone. Leave it alone. Every case uses a scratch server on 18769, run from the integration worktree. It serves two records: a copy of the mission-page-and-inbox record, set to review and with any summary removed, and a second copy, rri-unmerged, with every milestone marked unmerged.

The project's path is a throwaway git repo at /tmp/rri-m3/repo, and the summarizer is spawned there. The record's 121 findings are in the old shape, and none of them is a fix. So the setup adds two fixes, each headlined Walk seed: ..., so the summarizer has something it must put first. The setup also writes a fake claude into /tmp/rri-m3/nobin that always fails. Only case f1 uses it. Paste this in terminal 1:

Known going in

The RIO passed both tasks with these notes left open, plus one I hit while checking this setup. They are not cases, except where a case asks for your call. Note any you hit and think should be fixed.

huge failure line
Found while checking this setup, not by the RIO. When the spawn fails, the reason the page shows is the whole failed command line, and that includes the roughly 190 KB brief. So "The summary failed: ..." is a wall of text, not one line. Case f1 will show this, and as written it should fail.
status contradicts
When the spawn fails, the status line still says summarizing: a read-only session is reading the findings, because any 2xx sets it, while the block says the summary failed. This shows in f1.
persona vs brief
The session runs as the rio agent, whose standing contract asks for a verdict line and BLOCKER/NOTE labels. The brief asks for three bare bullets but never says "this is not a review", and nothing checks the file's shape. If the session writes a verdict, it lands on the page verbatim. Case l2 is where you would see it.
re-run wipes
Summarizing again clears the old bullets and deletes the old file before the new run lands. If the re-run fails, the old summary is gone. Case l3 asks for your call.
no timeout
A summarizer that hangs while listed as working holds the button at summarizing... for good. Only editing the record clears it. RIOs and walkthroughs behave the same way.
screen readers
Nothing announces when the bullets land or the run fails: the block has no live region. When the button disables under focus, focus moves to the block, which has no accessible name.
phone width
The button is 34px high. The contract asks for 44px at 600px wide or less. The gate's buttons have the same gap.
refused click
A refused post (HTTP 500) holds the button at summarizing... for 2 s with nothing running. The reason appears only on the status line.
