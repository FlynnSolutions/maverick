Progress reads itself · milestone 2

Cards

Progress on the mission page is now one card per task: lamp, title and the chips of its last move on the head row, and under it a timeline with one line per attempt. Your decisions are cards beside the task they concern, open questions are pinned at the top, and every automatic move is folded under show every move. A verdict chip scrolls to the task's triage row in Result, whose rows and summary bullets are cards too. After approval, the sections are set apart by space, not panels, and the ask's sentence spans its column. You walk all of it in the browser against a scratch copy of the finished mission-page-and-inbox mission.

Before you start: a scratch server on 18770

The server on 8767 runs main, which has neither moves nor the cards. Leave it alone. Every case uses a scratch server on 18770, run from the integration worktree. It serves two copies of the finished mission-page-and-inbox record. The first, mission-page-and-inbox, is the record as it is, with one addition: milestone 4 has a hold headlined Walk seed: ..., so Progress has a question to pin (the real mission has none open). The second, pri-gate, is set back to planned with every task pending, so you can see the page before approval. The project's path is a throwaway git repo at /tmp/pri-m2/repo, holding the mission's plan and a copy of the checklist. Nothing here writes outside /tmp/pri-m2. Paste this in terminal 1:
